# 周边去哪儿（高德地点推荐助手）

## 用途与适用场景

当用户给出**城市、起点坐标**和一句自然语言需求（如「附近咖啡馆，步行 15 分钟内，最多 3 家，优先近一点」）时，使用本 Skill 完成：

1. 理解地点类型、步行时间上限、推荐数量与排序偏好；
2. 调用高德 MCP 搜索附近真实地点；
3. 对每个候选调用步行路线规划，用**真实步行距离/时间**筛选；
4. 返回最多 3 个推荐，并简要说明理由。

各地点都是从同一起点出发的独立备选，**不要**串成多站行程。不要编造营业状态、排队、安静程度等未核实信息。

## 可用高德 MCP 工具（名称以平台实际暴露为准）

优先使用：

| 目的 | 典型工具名 | 关键参数 |
|------|------------|----------|
| 周边地点搜索 | `maps_around_search` | `keywords`（类型词）、`location`（`经度,纬度`）、可选 `radius`（米） |
| 关键词补充搜索 | `maps_text_search` | `keywords`、`city`（城市名） |
| 步行路线 | `maps_direction_walking` | `origin`、`destination`（均为 `经度,纬度`） |
| 地点详情（可选） | `maps_search_detail` | `id`（POI id） |
| 地址转坐标（仅缺坐标时） | `maps_geo` | `address`、可选 `city` |

说明：评测会提供明确起点坐标；若工具名略有差异（如 `maps_direction_walking_by_coordinates`），选择语义等价的步行规划工具即可。坐标格式一律为 **经度,纬度**（GCJ-02）。

## 执行步骤

### 1. 解析用户需求

从输入中提取并默认：

- **城市**（用于 text_search 或理解语境）
- **起点坐标** `origin = "lng,lat"`（评测给定；不要自行设备定位）
- **地点类型关键词** `keywords`（如：咖啡馆 / 咖啡厅、餐厅、公园、超市…；把口语映射为高德可搜关键词）
- **步行时间上限** `max_walk_minutes`（未说明则默认 20；「15 分钟内」→ 15）
- **推荐数量** `n`（未说明则默认 3，且最终不超过 3）
- **排序偏好**：出现「优先近一点 / 最近」→ 按步行时间升序；否则在满足时间约束的候选中按步行时间升序，同等时可用直线距离辅助

若缺少起点坐标：先说明需要起点坐标，不要猜测位置。

### 2. 搜索候选地点

1. 用起点 `location=origin` 调用 `maps_around_search`：
   - `keywords` = 解析出的类型词
   - `radius`：可先按「步行上限 × 约 80～100 米/分钟」估算（例如 15 分钟 → 1200～1500 米），不足时再略放大重试一次
2. 若周边结果明显过少，可用 `maps_text_search` 在同城补充，但仍须在下一步用**从同一起点出发的步行路线**过滤，不能只靠直线距离判定可达。
3. 从返回 POI 中收集：名称、地址、`location`（或可解析出的经纬度）、可选 `id`。丢弃无坐标的条目。

### 3. 步行路线校验（必须）

对每个候选（建议先取前 8～12 个较近的，避免过量调用）：

1. 调用 `maps_direction_walking`：
   - `origin` = 用户起点坐标
   - `destination` = 候选地点坐标
2. 从路径结果读取步行 **distance（米）** 与 **duration（秒）**。
3. 将 `duration/60` 作为预计步行分钟数。
4. **硬过滤**：`walk_minutes > max_walk_minutes` 的地点不得列入「符合条件的推荐」。
5. 禁止用直线距离冒充步行时间。

### 4. 筛选与排序

1. 仅保留通过步行时间上限的候选。
2. 按步行时间升序排序（「优先近一点」时必须如此）。
3. 截取前 `n` 个（`n≤3`）。
4. 若不足 `n` 个：少推，并说明「在当前步行限制内仅找到 X 家」或「未找到符合条件的地点」。
5. 查询失败或工具报错：如实说明服务异常，可建议放宽步行时间或更换类型；**禁止编造**地点与路线。

### 5. 生成回答

用列表或表格输出，每个推荐包含：

| 字段 | 要求 |
|------|------|
| 地点名称 | 来自高德返回 |
| 地址 | 来自高德返回 |
| 预计步行距离 | 来自步行路线（米或千米） |
| 预计步行时间 | 来自步行路线（分钟） |
| 推荐理由 | 一句，须有数据依据（如「步行约 8 分钟，距离起点最近」） |

对安静程度、排队、是否营业中等**无工具依据**的信息：标注「未核实」，或不写。

结果不足 / 失败时，在列表外加 1～2 句说明。

## 回答模板示例

```text
根据你的需求（类型：…，步行 ≤ … 分钟，最多 … 家），推荐如下：

1. **名称**
   - 地址：…
   - 步行：约 Xm / 约 Y 分钟
   - 理由：…

2. …

说明：…（若不足数量、有未核实信息或工具失败时填写）
```

## 失败与边界处理

- **工具调用失败**：说明哪一步失败，不要填充假 POI。
- **零结果**：明确「查询范围内未找到符合步行限制的地点」，可建议放宽时间或更换关键词。
- **数量不足**：返回实际找到的数量并解释。
- **不要**在 Skill 或回答中填写 API Key、密钥或个人隐私。

## 自检清单（执行前默念）

- [ ] 使用了周边/关键词搜索拿到真实 POI  
- [ ] 每个入选地点都有步行路线结果  
- [ ] 未把超时地点标为符合条件  
- [ ] 推荐 ≤ 3，排序符合「优先近」时的近→远  
- [ ] 未编造未核实信息
